## Logic Bugs

| ID | Sev | File | Line | Status |
|----|-----|------|------|--------|
| L1 | CRITICAL | `src/da_output.c` | 407 | FALSE POSITIVE — da_resume() never called irq_set_exclusive_handler; only irq_set_enabled |
| L2 | HIGH | `src/da_output.c` / `src/sector_cache.c` | 287 / 204 | [x] FIXED — bytes>0 guard added at all 4 call sites; error slot outputs silence |
| L3 | HIGH | `upstream/core/commo.c` | 121, 161 | FALSE POSITIVE — report_cmd==0 when Path C runs; FREE_CMD_BUFFER() already called by Path A |
| L4 | HIGH | `src/da_output.c` | 360 | [x] FIXED — s_paused=false moved to just before dma_channel_start() |
| L5 | MEDIUM | `src/disc_image.c` | 319 | [x] FIXED — underflow guard: fsize > file_offset check before division |
| L6 | MEDIUM | `src/sector_cache.c` | 209 | [x] FIXED — error path now mirrors success path flush_gen check |

### L1 — CRITICAL: double `irq_set_exclusive_handler()` panics on pause→resume
`da_resume()` calls `irq_set_exclusive_handler(DMA_IRQ_0, ...)` at line 407 — same call
already made in `da_start_play()`. The RP2350 SDK hard_asserts if a handler is already
registered. Every pause → resume sequence panics the device.
**Fix:** remove the registration from `da_resume()`; call only `irq_set_enabled(DMA_IRQ_0, true)`.

### L2 — HIGH: SD error slot played as stale audio data
`sector_cache_get()` returns `true` with `bytes_out == 0` for permanent-miss (error) slots.
`_dma_irq_handler()` treats `true` as a valid hit and calls `expand_to_i2s24()` on
uninitialized `s_raw` — random stale bytes played as audio on any SD read error.
**Fix:** after `sector_cache_get()` returns true, check `*bytes_out >= SECTOR_RAW_SIZE`;
zero the DMA buffer and skip expand if not.

### L3 — HIGH: stale `report_cmd` causes next command to appear as SAME_COMMAND
`report_cmd` is set to 1 in `RXD_CHECKSUM` / `ERR_SEND`. Only Path A clears it via
`FREE_CMD_BUFFER()`. If Path C (dispatcher/cmd_hndl) handles the command without clearing
`report_cmd`, the stale flag causes the next new command to be misidentified as
`COMMO_SAME_COMMAND`, silently dropping it.
**Fix:** Call `FREE_CMD_BUFFER(c)` (or `c->report_cmd = 0`) at the end of the Path C
dispatch block in `commo_bridge_poll()`.

### L4 — HIGH: `s_paused = false` set before DMA reconfigured; stale IRQ can fire
`da_resume()` sets `s_paused = false` at line 360 before the 10 ms spin-wait and before
DMA channels are reconfigured. A stale deferred IRQ firing in this window sees
`s_playing && !s_paused` and calls `dma_channel_set_read_addr()` on not-yet-configured
channels, pointing to arbitrary memory.
**Fix:** Keep `s_paused = true` through the spin-wait; clear it immediately before
`dma_channel_start()`.

### L5 — MEDIUM: unsigned underflow in BIN parser last-track length
In `disc_parse_bin()`, if a malformed CUE sets `file_offset > fsize`,
`fsize - trk->file_offset` underflows (both unsigned), producing a massive `next_lba`
that escapes the length clamp and corrupts `total_sectors`.
**Fix:** Add `if (fsize <= trk->file_offset) { trk->length_sectors = 0; continue; }`
before the division.

### L6 — MEDIUM: sector_cache error path skips flush_gen check
The SD error retry path marks a slot `valid = true` without checking `flush_gen`. If
`sector_cache_seek()` fires on Core 0 during the retry, the error sentinel is committed
at the post-seek slot index — false permanent-miss on the first sector of the new seek.
**Fix:** Mirror the success path: check `cache->flush_gen == gen_at_start` before
marking the error slot valid.

## Security Vulnerabilities

| ID | Sev | File | Line | Status |
|----|-----|------|------|--------|
| S1 | CRITICAL | `src/webserver.c` | 180–183 | [x] FIXED — NUL terminators added after strncpy for s_ssid, s_pass, s_host |
| S2 | HIGH | `src/webserver.c` | 670 | [x] FIXED — fw_token validated as exactly 32 lowercase hex chars in read_wifi_config() |
| S3 | HIGH | `src/webserver.c` | 900 | [x] FIXED — strcmp replaced with token_equal_ct() (XOR-accumulate constant-time) |
| S4 | HIGH | `src/webserver.c` | 764 | [x] FIXED — s_resp_buf moved to http_conn_t.resp_buf (per-connection, no shared-static race) |
| S5 | MEDIUM | `src/webserver.c` | 195–216 | [x] FIXED — generate_and_save_token() scans file for existing key before appending |
| S6 | MEDIUM | `src/webserver.c` | ~138 | [x] FIXED — request buffer increased from 512 to 1024 bytes |

### S1 — CRITICAL: `strncpy` leaves `s_ssid`/`s_pass`/`s_host` unterminated
`strncpy` does not write a NUL if the source fills the buffer. `s_ssid`, `s_pass`, and
`s_host` have no explicit termination (unlike `s_fw_token` at line 185). If `wifi_ssid`
is exactly 64 bytes, the CYW43 driver reads past `s_ssid` into `s_pass` — leaking the
WiFi password as part of the SSID string.
**Fix:** Add `s_ssid[sizeof(s_ssid)-1] = '\0'` etc. after each strncpy call.

### S2 — HIGH: `s_fw_token` injected raw into JavaScript string literal
`HCAT(..., s_fw_token)` embeds the token directly into a JS string with no escaping.
A config file with `fw_token = '; alert(1); var x='` injects arbitrary JavaScript.
Physical SD access required, but the injection path is real.
**Fix:** Validate `s_fw_token` at load time — reject any value that is not exactly
32 lowercase hex characters; zero the token and regenerate.

### S3 — HIGH: `strcmp` token comparison is not constant-time — timing oracle
`strcmp` exits at the first mismatching byte. On a LAN with measurable RTT, ~512 requests
can recover the 32-hex-char firmware-flash token one nibble at a time.
**Fix:** Replace with a constant-time comparison (XOR-accumulate all bytes, compare
accumulator to zero at end).

### S4 — HIGH: `s_resp_buf[4096]` shared static — overwritten on reentrant request
`s_resp_buf` is a module-level static used by all request handlers. The cover-serving
loop calls `cyw43_arch_poll()` mid-response; if that processes an incoming packet and
triggers `tls_recv_fn` for a second connection, a second `handle_request()` overwrites
`s_resp_buf` while the first response is still being written.
**Fix:** Move `s_resp_buf` into `conn_t` (per-connection), or stack-allocate in
`handle_request()`.

### S5 — MEDIUM: blank `fw_token` in config causes duplicate key appended every boot
If `fw_token = ` (empty after trim) exists in config, `s_fw_token` is empty and
`generate_and_save_token()` appends a second `fw_token` line. File grows unboundedly.
**Fix:** Check for presence of any `fw_token` key (even empty) before appending;
overwrite in place or skip.

### S6 — MEDIUM: 512-byte request buffer silently drops long-filename flash requests
`conn->request[512]` truncates when headers + URI + token header > 512 bytes. A firmware
filename of ~200 chars + API prefix + `X-FW-Token` + standard headers exceeds 512. The
`\r\n\r\n` marker is never found; request times out with no error response.
**Fix:** Increase to 1024 bytes, or return `413 Request Too Large` when the buffer fills
without finding the header terminator.

## Architecture & Performance

| ID | Sev | File | Line | Status |
|----|-----|------|------|--------|
| P1 | HIGH | `src/virtual_disc.c` | 367 | [x] FIXED — single-handle cache (s_cached_fil); f_open only on file change; vdisc_invalidate_fil() on disc_close + sim reset |
| P2 | LOW | `src/webserver.c` | router | [x] FIXED — !is_get && !is_post early guard returns 405 + Allow: GET, POST |
| P3 | MEDIUM | `src/main.c` | main loop | [x] FIXED — watchdog_enable(10000,1) before loop; watchdog_update() at each iteration |
| P4 | MEDIUM | `src/webserver.c` | 832 | [x] FIXED — HTML chunked write loop (4096 B/chunk, WANT_WRITE retry + cyw43_arch_poll) |

### P1 — HIGH: `f_open/f_close` per sector in virtual_disc.c burns sector budget
`read_file_sector()` opens, seeks, reads, and closes a FatFS handle for every 2048-byte
sector. FatFS `f_open` traverses the directory cluster chain each call (~1–5 ms). At 2×
CD speed (6.7 ms budget), this alone can exceed the delivery window.
**Fix:** Store a persistent `FIL` handle in `vdisc_entry_t`; open at `vdisc_mount()`,
close at `vdisc_close()`.

### P4 — MEDIUM: HTML page send truncated for large disc libraries (wolfSSL WANT_WRITE)
`wolfSSL_write(conn->ssl, html, 32768)` in `handle_request()` sends the full HTML page in
one call. TCP_SND_BUF = 8 × TCP_MSS = 11,680 bytes — less than the 32 KB page. wolfSSL
returns WANT_WRITE for the remainder; the code ignored it, so browsers received a broken
truncated page once the disc library grew past ~40–50 images.
**Fix:** chunked write loop matching the cover-serve pattern (4096-byte chunks, up to 20
WANT_WRITE retries per chunk with `cyw43_arch_poll()` in between). Fixed 2026-06-12.

### P2 — LOW: HTTP router returns 404 for wrong method on valid paths
Unknown HTTP methods fall through to 404 rather than 405 Method Not Allowed.
**Fix:** Check `!is_get && !is_post` early and return 405.

### P3 — MEDIUM: no hardware watchdog — main loop deadlock is permanent
Main loop never arms or kicks the watchdog. COMMO `pio_sm_get_blocking()` stall = permanent lockup.
**Fix:** `watchdog_enable(8000, 1)` at boot; `watchdog_update()` each main-loop iteration.
